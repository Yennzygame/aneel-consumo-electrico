2. La trampa de VlrMercado¶

DscDetalheMercado mezcla magnitudes físicas y monetarias. La tabla siguiente se calcula sobre el archivo 2024 completo, agregando por detalle:

  • unidad se infiere del nombre del detalle (R$, kWh, kW, %, conteo).
  • filas, media y maximo muestran el orden de magnitud de cada concepto.

from collections import defaultdict
from src.aneel_pipeline import parse_br

def unidad_de(detalle: str) -> str:
    if detalle.lower().startswith("número de consum"):
        return "conteo"
    if detalle.endswith("(%)"):
        return "%"
    if "(R$)" in detalle:
        return "R$"
    if "(kWh)" in detalle:
        return "kWh"
    if "(kW)" in detalle:
        return "kW"
    return "otra"

acc = defaultdict(lambda: [0, 0.0, 0.0])
ruta2024 = C.RAW_DIR / "samp-2024.csv"
for ch in pd.read_csv(ruta2024, sep=";", encoding="latin1", dtype=str,
                      usecols=["DscDetalheMercado", "VlrMercado"],
                      chunksize=250_000, low_memory=False):
    ch["valor"] = parse_br(ch["VlrMercado"])
    for det, g in ch.groupby("DscDetalheMercado"):
        a = acc[det]
        a[0] += len(g)
        a[1] += float(g["valor"].sum())
        a[2] = max(a[2], float(g["valor"].max()))

detalles = pd.DataFrame(
    [{"detalle": d, "unidad": unidad_de(d), "filas": v[0],
      "media": v[1] / v[0] if v[0] else np.nan, "maximo": v[2]}
     for d, v in acc.items()]
).sort_values("filas", ascending=False)
detalles.head(14).style.format({"filas": "{:,.0f}", "media": "{:,.1f}", "maximo": "{:,.1f}"})

Lectura. En 2024 hay ~1,1 millones de filas repartidas en R$, kWh, kW, % y conteos. Sumar VlrMercado sin separar produce un número sin significado: se estarían sumando ingresos con energía, demanda y porcentajes. Ese fue el origen del silhouette = 0,89 del trabajo anterior: un artefacto, no un hallazgo.

Regla del proyecto. Para consumo se usa solo Energia TUSD (kWh). Energia TE (kWh) contiene exactamente el mismo consumo (es el mismo kWh facturado, separado en dos componentes tarifarios); sumarlas lo duplicaría. Los R$, kW, % y conteos se excluyen del análisis de consumo y se usan solo como variables de contexto.

4. Unidad de análisis y cobertura¶

La unidad es:

segmento de mercado = distribuidora (SigAgenteDistribuidora) × clase de consumo (DscClasseConsumoMercado)

No es un consumidor individual: ANEEL publica el agregado mensual por clase dentro de cada distribuidora. Es la unidad sobre la que efectivamente se decide (tarifa, metas, priorización comercial), y es la más fina que los datos permiten.

Para que una unidad entre al clustering se exige cobertura temporal ≥ 95 % (≥ 65 de 68 meses) y capacidad de imputar huecos internos de hasta 2 meses. La cobertura se mide antes de imputar; por eso las 700 unidades incluidas terminan con serie completa.

Resultado. De las 833 unidades del panel, 99 corresponden a clases que no son mercado atendido (No se aplica, Consumo propio) y se descartan. Quedan 734 segmentos analizables; 700 cumplen cobertura y concentran el 99,4 % del consumo de esas clases. Los 34 restantes son segmentos pequeños o intermitentes (10,2 TWh, 0,6 %); excluirlos evita imputar series que no existen.

La figura 01_cobertura_temporal.png muestra el consumo mensual agregado; la caída de 2026-09 es el mes parcial del corte de datos (2,4 TWh frente a ~20 TWh de un mes completo) y por eso se excluye de la ventana.

5. Hallazgos de calidad que hay que poder defender¶

Hallazgo Evidencia Decisión
VlrMercado mezcla unidades 5 unidades distintas en DscDetalheMercado Analizar solo Energia TUSD (kWh)
TE y TUSD son el mismo kWh correlación 1,0 y mismos totales Nunca sumar ambas
10 % de valores negativos 664.448 filas, todas en R$ (ajustes/refacturación) No afectan energía: 0 negativos en kWh
Formatos numéricos brasileños 100 % con coma decimal; 54.767 con formato inválido parse_br + coerción a NaN
Cardinalidad de texto Serviço Público vs Serviço público Mapa explícito de clases
Mes parcial al final 2026-09 con 2,4 TWh Excluir 2026-09
Caso sensible en detalles Número de Consumidores (otros mercados) vs Número de consumidores (CATIVO) No normalizar mayúsculas en DscDetalheMercado

Los dos últimos puntos son importantes: normalizar todo a minúsculas habría mezclado consumidores del mercado libre con los del cativo y habría inflado el conteo. El filtro Regular + CATIVO se aplica antes de agregar.
